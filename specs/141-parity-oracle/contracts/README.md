# Development interfaces of feature 141

These files are the machine-readable form of `../spec.md`. They are development interfaces of the
oracle, not interfaces of the product. `spec.md` stands where a file and the specification differ.

| File | Mirrors | Hand-written or generated |
|---|---|---|
| `fixture-catalogue.json` | `spec.md` §O.2: families, scenarios, stubs, surfaces, features covered; the members of the pattern names; the ends on the reference; the scenarios that other features own; the reserved names and the requests that are no scenario | Generated by `tools/generate.py` |
| `stub-vocabulary.json` | §O.3: rules, verbs per kind of stub, harness stubs, names of executables | Hand-written, checked |
| `surfaces.json` | §O.4: S-01 to S-16, the run set, the roles of a transcript | Hand-written, checked |
| `register-map.json` | F141-FR-023: one entry per row of the register (DV-001 to DV-119 on 2026-09-30) with its handling | Generated once from `docs/ecosystem/consolidation.md` section 6, then corrected by hand; checked against the register |
| `layer-allowlist.json` | F141-FR-040: the entries of the second suite and what is not reachable | Hand-written |
| `per-os-expectations.json` | F141-FR-035 | Hand-written; every row `inferred` |
| `inventory-supplement.tsv` | F141-FR-017: the two rows proposed for the behaviour inventory, with the proposed ids B-2784 and B-2785 | Hand-written. The orchestrator decides the ids |
| `schemas/fixture.schema.json` | F141-FR-012: `fixture.json` | Hand-written |
| `schemas/waivers.schema.json` | F141-FR-022: the one waiver file | Hand-written |
| `schemas/test-declaration.schema.json` | §O.6: what a parity test declares | Hand-written |
| `schemas/transcript.schema.json` | F141-FR-011: one record of a transcript | Hand-written |
| `schemas/result.schema.json` | §O.5: the report of one comparison | Hand-written |
| `schemas/exercise-map.schema.json` | F141-FR-031 to F141-FR-033 | Hand-written |
| `tools/generate.py` | Writes the catalogue; `--check` compares every file with `spec.md`, the register and the data of feature 100, and checks every cited id | A tool of the specification |

The schemas carry `$id` in the form `urn:specstride:schema:internal:141:<name>/<major>`: the schemas of
the oracle are no contracts of the product, and the package is never shipped (W-100-16). The field
`schema` of every data file names the same id.

Run: `python3 specs/141-parity-oracle/contracts/tools/generate.py --check`.

Data of feature 100 that the oracle reads and never copies: `specs/100-specstride/contracts/data/`
`normalization.json`, `layout.json`, `layout-old-side.json`, `parity-profile.json`,
`exit-codes.json`, `stop-reasons.json`, `line-grammar.json`.
