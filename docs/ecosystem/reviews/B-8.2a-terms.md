# B-8.2a — Consistency: glossary, naming rule, closed harness lists

Reviewer: independent agent. Date: 2026-09-29.

Scope: `spec.md`, `plan.md` and `tasks.md` of the 41 features `specs/100-*` to `specs/149-*`, the
annexes of feature 100, and every file under `specs/1*/contracts/` (633 files under `specs/1*` in
all). The as-is directories `specs/002-*`, `specs/011-*`, `specs/028-*` were not read.

Method, in short:

| Check | How |
|---|---|
| Glossary | Read `consolidation.md` section 1 (50 terms), ruling 24 (`APPROVAL.md:68`) and `STAGE-B-RULES.md` section 5. A script stripped code spans and qualified forms, counted what was left per term and per feature, and printed the four words on each side of every bare use in `spec.md`. The contexts were read; the sentences cited below were read in the file |
| Naming rule | `grep -rniI` for the name and for spelling variants over `specs/1*` and `docs/ecosystem/`; `find -iname` for file names; every token that carries the name in the baseline (`git -C /root/specstride grep` at `9cab15d`: variables, file names, paths, the gateway and model names next to it) was searched as well; `/root/`, `/home/`, private address ranges |
| Closed lists | A script walked every JSON file of `specs/1*/contracts/` for `enum`, `const`, `default` and list values that hold a harness name; `closed-sets.json` was read for sets with harness literals; every requirement line outside the five adapter features that names a harness was read; `plan.md` and `tasks.md` of the non-adapter features were searched for harness names |
| Critic rules | Every requirement that names the critic together with session, model, pick, order or fallback, in all 41 specs; a count per feature of critic requirements against mentions of the diversity rule |
| Language | A list of 35 marketing words; library, runtime and package names and physical paths in requirement lines outside `## Constraints` |

The machine-specific name is not written in this report.

## Summary

| Severity | Count |
|---|---|

What holds: the machine-specific name appears nowhere under `specs/1*` and nowhere under
`docs/ecosystem/`, in no file name and in no contract file. No schema and no closed set enumerates
harnesses as a fixed set; the two sets that hold harness-like literals are declared open. No task
and no plan of a non-adapter feature branches on a harness name. The old meaning of "micro-loop"
is used nowhere. No marketing language was found. Every feature has a `## Constraints` section.

The three most serious findings:

1. B-8.2a-001 (high): three features give three different triggers for the one same-model warning,
   and F125-FR-026 opens with a MUST that the rest of the same requirement and F124-FR-037 deny.
2. B-8.2a-003 (medium): feature 126, which is core and not an adapter, branches on the harness
   names prime, dsh and Codex, against F100-FR-023.
3. B-8.2a-004 and B-8.2a-005 (medium): "run" is written for one engine start in requirements of
   seven features; in F119-FR-017 this changes what a logical name of feature 100 resolves to.
