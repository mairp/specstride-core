and tiers, across `spec.md`, `plan.md`, `tasks.md`, `data-model.md`, `quickstart.md`, `research.md`

What holds: the rename of commit `993cdac` is complete in every `spec.md`, `plan.md`, `tasks.md`,
`data-model.md` and `quickstart.md`. No old spelling survives there, except one in feature 110
itself (finding 006). The known values hold everywhere they are stated: the pause ceiling of 24 h,
2 workers with the ceiling 4, the nonce of 64 bits, `roles.refuseUnknown` on and off under
`parity`. The eight ranks are stated the same way in 100, 102, 106, 110 and 128. No feature lets
project configuration select a critic, declare a harness, set an endpoint, allow a plugin or accept
terms. The audience default `distributed`, Tier 2 as the default under it, and Tier 3 refused are
stated the same way in 100, 110, 113, 125, 130, 131, 134, 138 and 147.

What does not hold: the files under `contracts/` of the features were not part of the rename, and
the catalogue file of feature 110 disagrees with §X.7 on the value under `parity` of 14 keys.

The three most serious findings:

1. B-8.2e-001: features 138 and 130 bar a harness with unknown terms from being a default or an
   automatic pick only under the audience `distributed`. Ruling P14, F100-FR-093, F147-FR-008 and
   F124-FR-036 bar it always.
2. B-8.2e-002: `config-keys.tsv` of feature 110 gives "as default" as the value under `parity` for
   14 keys whose row of §X.7 gives another value. A profile built from the catalogue is not the
   `parity` profile.
3. B-8.2e-003: feature 118 reads six keys under `loop.yield.*` and three environment variables that
   no list holds. An unknown key refuses the launch (F100-FR-203), so 118 and 110 cannot both be
   built as written.
