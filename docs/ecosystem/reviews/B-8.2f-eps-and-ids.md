# B-8.2f — Consistency: extension points, requirement ids and cross-references

Reviewer: independent agent. Date: 2026-09-29.

Scope: all 41 features under `specs/1*` (`spec.md`, `plan.md`, `tasks.md`, annexes of feature 100, and
for the id checks every `.md`, `.json` and `.tsv` file below them), against feature 100
(`spec.md` "Extension points", annexes A to H and X, `contracts/extension-points/*.json`,
`contracts/data/package-graph.json`, `layers.json`), `architecture.md` sections 5 and 14,
`feature-briefs.md` sections A.1a, A.3 and D.3, `consolidation.md` section 6, `CLARIFY-QUEUE.md` and the
traceability files.

Method: eleven small Python scripts, kept in the scratch directory `B-8.2f/` (`ep.py`, `ep2.py`, `ops.py`,
`ids.py`, `moved.py`, `stale.py`, `tests.py`, `proves2.py`, `splittests.py`, `cite.py`, `refs.py`), plus
`grep` and reading of every place reported. Every finding below was read in the file before it was
written down. Nothing in the repository was changed other than this report.

What holds:

- All 633 `ep:` lines that name an extension point use the EP number, the id string and the version of
  feature 100. No version mismatch and no wrong id string exists anywhere.
- 1,892 requirement ids are defined; none is defined twice; none sits in a directory of another number.
  Every cited id that is defined nowhere (163) is an old id of a split, and every one of those is in the
  old-to-new tables. The tables of both parts agree for all nine splits. No old id is reused.
- Every `proves:` id in every `tasks.md` is an origin of a requirement of the same feature (directly, or
  through the cluster of the traceability files) or an id of that feature. Task ids are unique in all 41
  task lists.
- Every `DV-nnn`, `FX-nn` and `CQ-nnn` cited anywhere exists. No `DV-new-*` placeholder is left in a spec,
  plan or task list.
- Tier 2 features cite requirement ids of other tier 2 features in two places only.

The three most serious findings:

1. **B-8.2f-001**: the owner of EP-16 is 115 in feature 100's extension-point table, annex C and the
   generated contract, and 116 in the briefs, in feature 116 and in annex X of feature 100 itself.
2. **B-8.2f-002**: the owner of the engine services of EP-04 and of the tree-store service is 142 in
   annex D of feature 100 and 143 in the briefs, in feature 143 and in annex X of feature 100.
3. **B-8.2f-003**: features 134 and 138 place the shared JSONL reader and the pi adapter in different
   packages, and the package of 134 is not in the package graph.
